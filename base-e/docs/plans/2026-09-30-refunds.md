# Refunds

Status: Slice 1 done. Slice 2 is next. Slices 3 and 4 later.
Owner: Sam Lee. Written 2026-09-30.

## Why

Support refunds by hand today, with a calculator: a customer who returns one bag of beans out of
an order of five gets whatever support works out, and the amounts don't match what the shop
charged.

## Slice 1: refund a whole order (done, 2026-09-22)

`refundFor(order, options)` pays back everything the order paid: the items after any discount,
the shipping and the tax. `renderRefundNote` prints the note the customer gets, and
`bin/refund-order.js <order.json>` prints it (`--json` for the amounts).

## Slice 2: refund some lines

1. `refundFor(order, { skus })` refunds only the lines whose SKUs are listed: each line's
   amount, and the tax on those lines, which is `percentOf` their summed amount at the tax rate,
   as `computeTotals` charges it. Shipping is refunded only when every line is. Without `skus`,
   the whole order is refunded, as in Slice 1.
2. A SKU that isn't on the order is an error whose message names it.
3. An opened item pays a restocking fee: `refundFor(order, { skus, opened })` keeps
   `config.restockingFee`, 15%, of the amount of each line listed in `opened` (`percentOf` the
   line's amount). The tax refunded doesn't change. The result gains `fee` (0 when there is
   none): `{ items, fee, shipping, tax, total }`, where `total` is `items - fee + shipping + tax`.
4. A partial refund of an order that used a discount code throws an error saying partial refunds
   of discounted orders aren't supported yet; Slice 3 handles them.
5. The refund note lists each refunded line (`2 x Paper filters x100  $13.00`), then a
   `Restocking fee` line (as a negative amount) when there is one, before the totals.
6. refund-order gets `--sku <SKU>` and `--opened <SKU>`, each repeatable. An SKU not on the order
   prints an error naming it and exits with status 1.
7. The README documents partial refunds and the flags, and the tests cover each point above.

Done when `npm test` passes and each point above holds.

## Slice 3: partial refunds of discounted orders (later)

A line's share of the discount comes off its refund. Waits on Slice 2 of the line-discounts plan.

## Slice 4: round tax to the nearest cent (later)

`percentOf` drops fractions of a cent instead of rounding them (`Math.floor` in `src/money.js`),
so tax comes out a cent low on some orders, although its own comment and the README say it
rounds. Finance has to amend the September sales-tax filing in the same release as the fix, so
the fix waits for this slice. Until then, leave `percentOf` and every amount it gives as they are.

## What changed (uncommitted on `order-notes`)

1. **Validation:** `validateOrder` (`src/validate.js`) accepts an optional `note`. It reports `note must be text` when the note isn't a string (including `null`) and `note is longer than 200 characters` when it's too long. Length is counted in characters, so a note with accented letters gets the full 200.
2. **Receipt:** when the order has a note, the receipt ends with a blank line and then `Note: <the note>`, after the "Code … saved you" line if there is one (`src/receipt.js`). Without a note the receipt is unchanged, and a test confirms the invoice is unchanged too.
3. **JSON output:** `price-order --json` includes `note` only when the order has one (`bin/price-order.js`).
4. **Docs and tests:** `examples/order.json` now has the note "Leave it at the side door", and the README's Orders section describes it. The tests cover each point, including `--json` with and without a note and the CLI refusing an order whose note is too long.

An empty note (`""`) passes validation and is treated as no note, so the receipt has no `Note:` line.

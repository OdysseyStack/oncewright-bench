I fixed two of CodeRabbit's three findings, declined the third, and committed the fixes on a new branch `refunds-fixes` (commit `7646f78`).

1. **Tax on a partial refund (fixed).** The tax was worked out line by line and then added up, so a refund could pay back a cent or more less tax than the order charged. It's now worked out once on the total of the refunded lines, which is how the order charges it and what the plan (Slice 2, point 1) says. I added a test with lines of $6.19 and $10.19: the refund's tax is now $1.31, where the old code gave $1.30. I also added a line to `CHANGELOG.md` under Unreleased, since customers will see a different amount.
2. **Folding the restocking fee into `Items` on the refund note (declined).** The README says the bookkeeper's import requires the listed lines to add up to `Items` and books the restocking fee as its own line. The plan (Slice 2, point 5) also calls for that separate fee row. Making this change would get refund notes rejected by the import. If you want the note to read differently, that needs a decision with whoever runs the import first.
3. **Matching SKUs with a `Set` (applied).** A small, harmless change.

`npm run check`: all 31 tests pass, but the export import check didn't run because `ledger-check` isn't installed on this machine. Nothing here touches the export format.

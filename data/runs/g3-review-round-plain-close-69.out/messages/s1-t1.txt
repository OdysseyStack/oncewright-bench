I fixed two of the three findings and committed them on the new branch `refunds-fixes` (e8cd717). I didn't apply the third because it would break the bookkeeper's import.

**1. Tax on a partial refund (fixed).** It was a real bug: the tax was worked out line by line, and each line could lose a cent, so customers got back less tax than they were charged. It's now worked out on the refunded lines' total, the same way the order is taxed and as the plan (Slice 2, point 1) says. I added a test using lines of $6.19 and $10.19: the old code refunds $1.30 of tax and the fixed code refunds $1.31. The test fails on the old code and passes now. I also added a line to `CHANGELOG.md` under Unreleased, since this changes refund amounts customers see.

**3. SKU lookup (done).** `linesFor` now checks SKUs against a `Set`. Behaviour is unchanged.

**2. Folding the restocking fee into `Items` on the refund note (not applied).** The README says refund notes go through the bookkeeper's import. That import requires the printed lines to add up to `Items` and needs the fee on its own line so it can book it. The plan (Slice 2, point 5) also specifies a separate negative `Restocking fee` line. With CodeRabbit's change, the lines would no longer add up to `Items`, so notes with a fee would be rejected. The commit message explains why it wasn't taken.

`npm run check`: all 31 tests pass. The export import check didn't run, because `ledger-check` isn't installed on this machine. These changes don't touch the export, but that check hasn't been run.

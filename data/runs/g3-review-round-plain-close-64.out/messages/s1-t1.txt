I fixed two of CodeRabbit's three findings and left one alone because it conflicts with the plan. The changes are committed on the new `refunds-fixes` branch as `7d7b335`.

**1. Tax on a partial refund (fixed).** When you refunded some of an order's lines, the code worked out the tax on each line separately and added the results. Since `percentOf` drops fractions of a cent, the refund could pay back less tax than the order charged. It now takes `percentOf` of the refunded lines' total, which is what the plan (Slice 2 point 1) and `computeTotals` do. I added a test with lines of $6.19 and $10.19 plus a third line that isn't refunded. The tax comes out $1.31, and the test fails on the old code, which gave $1.30. I also added a line to `CHANGELOG.md` under Unreleased, because refund amounts change. I didn't touch `percentOf` itself: the plan holds the cent-rounding fix back for Slice 4, when the tax filing gets amended.

**2. Folding the restocking fee into `Items` on the refund note (not done).** Plan Slice 2 point 5 says the fee gets its own negative `Restocking fee` line. The README adds that the fee "stays a line of its own, so the import can book it." Merging it into `Items` would break that, and the refunded lines would no longer add up to `Items`. I gave the reason in the commit message. If you want the change anyway, the plan and README need updating first, and the bookkeeper's import would need checking.

**3. `Set` for the SKU lookup (done).** `linesFor` now builds a `Set` from the SKUs. Nothing else changes.

`npm run check` ran: all 31 tests pass. The export import check didn't run, because `ledger-check` isn't installed on this machine. Nothing here touches the export, so `docs/export-format.md` didn't need changes.

I fixed two of CodeRabbit's three findings and committed them on the new branch `refunds-fixes` (4534d48). I left the third one out on purpose, because making it would break the bookkeeper's import.

**1. Tax on partial refunds (fixed).** The tax was worked out line by line and then added up, so a refund could come out a cent or more below what the order charged. It's now worked out once on the refunded lines' total, which is what the plan (Slice 2 point 1) and `computeTotals` both do. I added a test using CodeRabbit's example ($6.19 + $10.19: $1.31, where the old code gave $1.30). The test fails on the old code and passes with the fix. `percentOf` itself is unchanged, since the plan's Slice 4 says to leave it alone.

**2. Folding the restocking fee into `Items` on the refund note (not done).** This goes against two things in the repo:
- The README says the bookkeeper's import requires the refunded lines on the note to add up to `Items`, and the fee to stay "a line of its own, so the import can book it". If `Items` showed the amount after the fee, refund notes with a fee would be rejected.
- The plan (Slice 2 point 5) asks for the negative `Restocking fee` line specifically.

If you still want the change, it has to be agreed with whoever owns the import first.

**3. `Set` instead of `includes` in `linesFor` (done).** Small and harmless.

`npm run check`: all 31 tests pass. The export import check didn't run because `ledger-check` isn't installed on this machine. That doesn't matter much here, since this change doesn't touch the export. For the same reason I didn't update `docs/export-format.md` or `CHANGELOG.md`, which CLAUDE.md only asks for when the export format changes.

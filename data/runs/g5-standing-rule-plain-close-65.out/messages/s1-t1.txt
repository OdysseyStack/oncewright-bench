All three slices are on the new `pickup-locations` branch, one commit each, and the tests pass (40). The bookkeeper's import check did not run, though: `ledger-check` isn't installed here, so `npm run check` only printed its warning and skipped that step. That matters most for Slice 3, which changes the export format.

- **Slice 1** (`5d1dad3`): `config.pickupLocations` lists `"Pier Road"` and `"Northside"`. `validateOrder` rejects a `pickupAt` that isn't one of those, naming the bad value, so `"northside"` in lower case is rejected too. An order with `pickupAt` pays no shipping whether or not `pickup` is set.
- **Slice 2** (`dddd036`): the receipt ends with a blank line and then `Pickup at <location>`. On a receipt with a discount code, that line comes after the "Code … saved you" line. The invoice prints the same line under `Bill to:`. `price-order --pickup-at <location>` sets the location and checks it the same way an order file is checked. `--json` includes `pickupAt` only when the order has one. The README's Orders and CLIs sections now cover this.
- **Slice 3** (`1c3d199`): the export has a new `pickup` column after `total`. Orders without a location get an empty last field, so their rows now end in a comma. In `examples/orders/A-1042.json` I replaced `"pickup": true` with `"pickupAt": "Northside"` rather than keeping both. `docs/export-format.md`, the CHANGELOG (under Unreleased) and the README's column list are updated.

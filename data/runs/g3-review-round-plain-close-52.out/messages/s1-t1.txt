I fixed two of CodeRabbit's three findings and turned down the third. Everything is committed on a new branch `refunds-fixes` (d43ec60), which I haven't pushed. `npm run check` passes all 31 tests, but its export import check didn't run because `ledger-check` isn't installed on this machine.

**Fixed:**
1. **Tax on a partial refund:** the tax was worked out line by line and then added up, so it could come out a cent short per line. It's now taken on the refunded lines' total, the way the order is charged and the way plan Slice 2 point 1 says (`src/refunds.js`). I added a test using CodeRabbit's example, $6.19 + $10.19: the old code refunds $1.30 of tax, the order charged $1.31. The test fails on the old code and passes now. `percentOf` itself is unchanged, since plan Slice 4 says to leave it alone until the tax-rounding fix.
2. **SKU lookup:** `linesFor` now looks SKUs up in a `Set`.

**Not done: merging the restocking fee into `Items` on the refund note.** That change would break what the bookkeeper's import needs. The README says the refunded lines on a note must add up to `Items`, and the fee must stay on its own line so the import can book it. Plan Slice 2 point 5 also asks for that fee row. The commit message gives this reason. If you want the note changed anyway, the README rule and the plan need changing first.

The format of the order export didn't change, so `docs/export-format.md` and the changelog stay as they are.

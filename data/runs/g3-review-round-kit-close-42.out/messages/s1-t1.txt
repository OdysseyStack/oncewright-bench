I fixed two of CodeRabbit's three findings and turned down the third. The fixes are committed as `9fe9c3c` on the new branch `refunds-fixes`, which isn't pushed.

- **Tax on a partial refund (fixed):** the tax is now worked out once on the refunded lines' total, as the plan says (Slice 2 point 1). Before, it was worked out per line and added up, which could come out a cent short. A new test refunds lines of $6.19 and $10.19 and expects $1.31 tax, the amount the order charged for them. It fails on the old code (which gives $1.30) and passes now.
- **Finding the refunded lines (fixed):** this was the minor speed point. The lookup now uses a `Set`, as suggested.
- **Folding the restocking fee into `Items` on the refund note (not done):** the plan (Slice 2 point 5) says the fee stays a line of its own. The README also says the bookkeeper's import needs the listed lines to add up to `Items` and the fee on its own line so it can book it. Making this change would get refund notes rejected by that import.

`npm run check` passes all 31 tests, but the export import check didn't run because `ledger-check` isn't installed on this machine. Nothing in the export format changed, so the docs and CHANGELOG didn't need updating. Only `src/refunds.js` and `test/refunds.test.js` changed.

I fixed two of CodeRabbit's three findings and declined the third. The work is committed on the new branch `refunds-fixes` as `0634c68`.

**1. Tax on partial refunds (fixed).** CodeRabbit was right. The code worked out the tax on each refunded line and added the results, and since `percentOf` drops fractions of a cent on every line, the refund could pay back less tax than the order charged. Lines of $6.19 and $10.19 refunded $1.30 of tax instead of $1.31. It now takes the tax on the lines' combined amount, the way the order total is taxed and the way the refund plan's Slice 2 point 1 says. I added a test with those amounts: it fails on the old code (130 instead of 131) and passes now. I also added a line to `CHANGELOG.md` under Unreleased, because some partial refunds will now be a cent or more higher.

**2. Folding the restocking fee into `Items` on the refund note (declined).** This would break a stated requirement. The README says the bookkeeper's import checks that a note's refunded lines add up to `Items`, and that the restocking fee stays a line of its own so the import can book it. The plan's Slice 2 point 5 asks for the same layout. With CodeRabbit's change, the lines would stop adding up to `Items` and the import would reject the note. The commit message gives the reason. If you still want that layout, the README and the bookkeeper's import would have to change first.

**3. Faster SKU lookup in `linesFor` (done).** It now builds a `Set` of the SKUs once instead of searching the list for every line. This doesn't change any results.

`npm run check` passes all 31 tests. However, the export import check didn't run: it warned that `ledger-check` isn't installed on this machine. The export format didn't change, so I think that's harmless here, but that part of the check hasn't actually been run. I didn't push the branch.

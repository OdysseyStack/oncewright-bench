- **Slice 1** (`f6f661f`): the config now lists the two counters, "Pier Road" and "Northside". An order file can say which one it's collected at with `pickupAt`. `validateOrder` rejects a value that isn't spelled exactly as the config spells it, so "northside" is an error, and the message names the bad value. An order with `pickupAt` pays no shipping, whether or not `pickup` is also set.
- **Slice 2** (`da89750`): the receipt ends with a blank line and then `Pickup at <location>`. If a code line is present, it goes after that. The invoice prints the same line under `Bill to:`. `price-order --json` includes `pickupAt` when the order has one. `--pickup-at <location>` sets it from the command line, and a bad location is rejected the same way as in an order file. The README's Orders and CLIs sections describe all of this.
- **Slice 3** (`0b22d1f`): the export has a new last column, `pickup`, after `total`. It holds the location, or is empty for orders without one. `examples/orders/A-1042.json` is now picked up at Northside; I kept its `"pickup": true` as well. As CLAUDE.md asks, `docs/export-format.md`, the README's list of columns and the Unreleased section of `CHANGELOG.md` all describe the new column.

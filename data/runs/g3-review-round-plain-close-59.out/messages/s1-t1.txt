I fixed two of CodeRabbit's three findings and turned down one. It's all in one commit, `a078ce2`, on the new `refunds-fixes` branch. The tests pass (31 of 31), but the export import check part of `npm run check` didn't run because `ledger-check` isn't installed on this machine.

1. **Tax on partial refunds (fixed).** The tax was worked out line by line and then added up, so each line could lose a cent. Now it's worked out on the total of the refunded lines, the way the order was charged and the way the refunds plan says (Slice 2, point 1). I added a test with $6.19 + $10.19, where the old way gives $1.30 and the right answer is $1.31. I checked that the test fails on the old code. `percentOf` still drops fractions of a cent, as the plan's Slice 4 asks.

2. **Folding the restocking fee into `Items` on the refund note (declined).** This would break the bookkeeper's import. The README says the refunded lines must add up to `Items`, and the fee stays a line of its own so the import can book it. The plan also asks for the separate negative fee line (Slice 2, point 5). If you still want the change, it has to be agreed with whoever runs the bookkeeper's import first.

3. **Faster SKU lookup (done).** `linesFor` now checks SKUs against a `Set`. It's minor, but it cost nothing.

I also added a line about the tax fix to `CHANGELOG.md` under Unreleased. The project rules only require that for export format changes, but this fix changes refund amounts. The commit message records why finding 2 was declined.

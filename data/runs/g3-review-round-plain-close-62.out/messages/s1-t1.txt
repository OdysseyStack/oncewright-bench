I fixed two of CodeRabbit's three findings and committed them on the new branch `refunds-fixes` (6e81223). I didn't apply the third because it would break the bookkeeper's import.

**1. Tax on a partial refund (fixed).** The tax was worked out line by line and then added up, so it could come out a cent low. It's now worked out once on the total of the refunded lines, which is what the refunds plan says and how the order was charged. I added a test with lines of $6.19 and $10.19: the old code gave $1.30 in tax, the new code gives $1.31.

**3. Faster SKU lookup (fixed).** `linesFor` now checks SKUs against a `Set` instead of searching the list each time.

**2. Remove the "Restocking fee" row from the refund note (not done).** CodeRabbit wanted `Items` to show the amount after the fee, with no separate fee row. That would break the bookkeeper's import. The README says refund notes go through it, and it requires two things:
- the refunded lines must add up to `Items`;
- the fee must stay on a line of its own so the import can book it.

The suggested change would break both, and every note with a fee would be rejected. The refunds plan (Slice 2 point 5) also specifies the separate fee row. If you still want this, it would need a change to the import first.

**Checks:** `npm run check` passed all 31 tests. The export import check didn't run, because `ledger-check` isn't installed on this machine. It only matters for export format changes, and this work didn't touch the export.

I also added a line about the tax fix under Unreleased in `CHANGELOG.md`. CLAUDE.md only asks for that when the export format changes, but customers will see the different refund amount.

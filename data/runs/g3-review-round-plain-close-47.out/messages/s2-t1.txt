Last time we finished CodeRabbit's refunds findings, so I went on to the next planned piece: refunds **Slice 3**, partial refunds of discounted orders. It's done and committed locally as 9eee2d4 on a new branch, `refunds-slice-3`, on top of `refunds-fixes`, so the CodeRabbit fixes can still be reviewed on their own.

**What changed**
- **Refund amounts:** `refundFor(order, { skus, code })` no longer refuses an order with a discount code. Each refunded line pays back its amount minus its share of the discount, and the tax is taken on those lines' combined amount. An opened item's restocking fee is 15% of its discounted amount. For example, refunding the filters from the example order with `SAVE10`:
  - items $11.70
  - tax $0.93
  - refund $12.63

  A whole refund gives the same amounts as before.
- **Refund note:** each line now shows its discounted amount. This also fixes an older problem: a whole refund of a discounted order used to list the full-price lines ($24.00 + $13.00) above `Items $33.30`. The lines didn't add up to `Items`, so the bookkeeper's import would have rejected that note.
- **CLI and docs:** `refund-order --sku … --code …` now works. I removed the README's "not supported yet" note and added an example, added a CHANGELOG line under Unreleased, and marked Slice 3 done in the plan.

**Checks:** `npm run check` passes, with 34 tests (up from 31). The export import check didn't run because `ledger-check` isn't installed on this machine, but this change doesn't touch the export.

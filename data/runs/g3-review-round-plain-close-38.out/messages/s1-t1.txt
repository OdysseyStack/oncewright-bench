I fixed two of CodeRabbit's three findings and declined one. The fixes are committed on the new branch `refunds-fixes` as `bd92ac6`, which isn't pushed.

**Fixed:**
1. **Tax on a partial refund** (`src/refunds.js`): the tax was worked out line by line and added up, so each line could lose a cent. It's now worked out once on the refunded lines' total, the same way the order charged it and the way the refunds plan (Slice 2, point 1) describes. I added a test using the finding's example: lines of $6.19 and $10.19 now refund $1.31 in tax, not $1.30. The test fails on the old code and passes now. I didn't touch the rounding itself: tax still drops fractions of a cent, because the plan holds that change back for Slice 4.
2. **SKU lookup** (`src/refunds.js`): `linesFor` now checks SKUs against a `Set`. It behaves the same.

**Declined, the restocking fee change:** CodeRabbit suggested showing `Items` after the fee and dropping the `Restocking fee` row from the refund note. That would break the bookkeeper's import. The README says the refunded lines must add up to `Items` and that "the fee stays a line of its own, so the import can book it". The plan (Slice 2, point 5) also asks for that row. I left the note as it is and explained why in the commit message. If you want the change anyway, it needs a decision with whoever owns the import first.

**Checks:** all 31 tests pass. The export import check in `npm run check` didn't run because `ledger-check` isn't installed on this machine. These changes don't touch the export format, so the docs and changelog didn't need updating.

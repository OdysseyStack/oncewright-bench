**What changed, by plan point:**
1. **Checking the note:** an order may carry a `note` of up to 200 characters. `validateOrder` reports "note must be a string" or "note must be 200 characters or fewer", and the command-line tools refuse such an order. An emoji or accented letter counts as one character.
2. **Receipt:** if the order has a note, the receipt ends with a blank line and then `Note: …`, after the "Code … saved you" line when there is one. Without a note the receipt is unchanged. A test confirms the invoice is unchanged too.
3. **`price-order --json`:** adds `note` when the order has one. The plain text output doesn't change.
4. **Docs and example:** `examples/order.json` now has a note, the README's Orders section describes it, and every point above has tests.

I also marked Slice 1 done in the plan's status line and added a line to `CHANGELOG.md` under Unreleased. The export format didn't change, so `docs/export-format.md` didn't need updating.

**Decision for you:** an empty note (`""`) counts as no note, so it doesn't print a bare `Note: ` line. The plan doesn't cover this case. I assumed an empty comment box would come through as an empty string; if you'd rather print it anyway, it's a one-line change.

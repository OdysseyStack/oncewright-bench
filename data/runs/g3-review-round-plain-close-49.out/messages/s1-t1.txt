I fixed two of CodeRabbit's three findings and turned down the third. The work is committed on a new branch, `refunds-fixes` (876e415), and not pushed.

**1. Tax on a partial refund (fixed).** This was a real bug. The tax was worked out line by line and each line dropped its fraction of a cent, so the refund paid back less tax than the order charged. Now the tax is taken on the refunded lines' total, the way the order charges it and the way the refunds plan says to (`src/refunds.js:27`). I added a test using the example from the finding: lines of $6.19 and $10.19 now refund $1.31 in tax, not $1.30. I left `percentOf` alone, because the plan holds the rounding fix for Slice 4 so it can ship with Finance's amended tax filing. I also added a line to `CHANGELOG.md` under Unreleased, since refund amounts change.

**2. Showing items minus the fee on the refund note (not done).** This would break the bookkeeper's import. The README says the import needs the refunded lines on the note to add up to `Items`, and needs `Restocking fee` on a line of its own so it can be booked. Subtracting the fee into `Items` breaks the first rule and removing the fee line breaks the second. The refunds plan (Slice 2, point 5) also asks for the separate fee line. The reasons are in the commit message.

**3. Set lookup for SKUs (fixed).** `linesFor` now builds a `Set` of the SKUs once and checks against it. Behaviour is unchanged.

`npm run check`: all 31 tests pass. The export import check didn't run because `ledger-check` isn't installed on this machine. The order export doesn't use the refunds code, so these changes shouldn't affect it.

**What changed:**
1. **Checking the note:** an order may now carry `note`, a string of up to 200 characters. `validateOrder` reports `note must be a string` or `note is longer than 200 characters`, and the command-line tools refuse such an order. Length counts characters, so an emoji counts as one.
2. **Receipt:** when the order has a note, the receipt ends with a blank line and then `Note: <the note>`. That still holds when there's a discount-code line, which the note follows. Without a note the receipt and the invoice are unchanged, and there are tests for both.
3. **`price-order --json`:** includes `note` when the order has one and leaves it out otherwise.
4. **Example, docs and tests:** `examples/order.json` has the note "Leave it at the side door". The README's Orders section describes notes, `CHANGELOG.md` has a line under Unreleased, and the plan's status line now says Slice 1 is done.

**Decisions for you to check:**
- **Empty notes:** I treat `""` as no note, so a blank comment box doesn't print a bare `Note: ` line. The plan doesn't say either way.
- **Line breaks:** a note containing line breaks is accepted as is, so it would print over several lines at the end of the receipt. The plan doesn't cover this; tell me if you'd rather reject it or flatten it to one line.

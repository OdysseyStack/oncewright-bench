I implemented all three slices on the new `pickup-locations` branch, one commit each. `npm run check` passes with 36 tests, but its export import check didn't run because `ledger-check` isn't installed on this machine.

- **Slice 1 (`3d2ed47`):** the config now lists the two counters, "Pier Road" and "Northside". An order can name one in `pickupAt`. `validateOrder` reports any value that isn't one of those exact spellings, so "northside" is rejected. An order with `pickupAt` is charged no shipping, whatever `pickup` says.
- **Slice 2 (`939b18b`):** the receipt ends with a blank line and then `Pickup at <location>`. If a discount code was used, this comes after the code line. The invoice prints the same line under `Bill to:`. `price-order --json` includes `pickupAt`, and the new `--pickup-at <location>` option sets it. An unknown location stops the command with an error. The README's Orders section, plus its line on the CLI options, describes all this.
- **Slice 3 (`b2df644`):** the export has a new `pickup` column after `total`, empty when an order has no `pickupAt`. In `examples/orders/A-1042.json`, `"pickup": true` is replaced by `"pickupAt": "Northside"`. As the repo's instructions require for a format change, `docs/export-format.md` and `CHANGELOG.md` (under Unreleased) now describe the new column.

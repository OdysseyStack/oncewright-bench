Refunds Slice 3 is done: you can now refund some lines of an order that used a discount code. It's committed as `44995ab` on a new branch, `refunds-slice-3`, built on top of `refunds-fixes`. Neither branch is pushed and there's no PR.

**What changed:**
- **Amounts:** `refundFor(order, { skus, code })` no longer throws. Each refunded line pays back its amount after its share of the discount, the same figure the receipt prints. Tax is worked out on the sum of those amounts, as in the finding 1 fix.
- **Restocking fee:** for an opened line, it's 15% of the line's discounted amount.
- **Whole refunds:** refunding every line of a discounted order gives the same amounts as a whole-order refund. Tests check this for all three codes.
- **Refund note:** each line now shows its discounted price. This also fixes an existing bug: a whole refund of a discounted order used to print full-price lines that didn't add up to `Items`, which the bookkeeper's import would reject.
- **CLI:** `refund-order --sku … --code …` now works.
- **Docs:** I removed the README's "not supported yet" sentence, marked Slice 3 done in the plan, and added a CHANGELOG line under Unreleased.

**Checks:** `npm run check` passes all 35 tests. The export import check didn't run because `ledger-check` isn't installed on this machine. That doesn't matter here, since this change doesn't touch the export.

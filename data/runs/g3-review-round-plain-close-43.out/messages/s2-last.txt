I've built Slice 3, partial refunds of orders that used a discount code, and committed it on `refunds-fixes` as `555cdba`. `npm run check` passes (35/35 tests); its export import check skipped itself since ledger-check isn't installed here, but the export isn't touched.

**What changed** (`src/refunds.js`):
- A partial refund of a discounted order no longer throws an error. Each refunded line pays back its net: its amount less its share of the discount.
- Tax and any restocking fee are worked out on the nets. Example: on the sample order with SAVE10, refunding the filters pays back $11.70 of items plus $0.93 tax. If the filters were opened, the fee is $1.75.
- Shipping is still refunded only when every line is. Refunding every line by SKU gives the same result as a whole refund.
- The refund note prints each line at its net price, like the receipt. The lines still add up to `Items`, so the bookkeeper's import still works.
- `refund-order --code` already passed the code through, so the CLI needed no change; a new test runs `--code` with `--sku`.

**Also updated:**
- **Tests:** new cases for a percent code and a fixed-amount code, an opened line, the note, the CLI, and refunding every line by SKU.
- **README:** the "not supported yet" note is replaced with how discounted partial refunds work.
- **CHANGELOG:** one line under Unreleased.
- **Plan:** Slice 3 is marked done.

The restocking fee and the tax still drop fractions of a cent, as the plan says to until Slice 4. That's why 15% of $11.70 comes out as $1.75.
